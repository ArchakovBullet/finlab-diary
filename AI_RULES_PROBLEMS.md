# ПРАВИЛО РАБОТЫ ДЛЯ AI: ВЫЯВЛЕНИЕ И УСТРАНЕНИЕ ПРОБЛЕМ

## Базовые принципы
1. Тщательно анализировать данные на предмет несоответствий и потенциальных проблем.
2. Не игнорировать недочёты и неточности в данных.
3. Своевременно информировать напарника о выявленных проблемах.
4. Предлагать эффективные пути устранения.
5. Если могу исправить самостоятельно — уведомить и исправить.

## Превентивный анализ
- Не ждать пока напарник заметит проблему.
- При каждом запуске дашборда или сборщика — проверять логи, смотреть аномалии.
- Сверять данные: сводка vs сканер, бот vs дашборд.
- Проверять свежесть данных для каждого тикера (check_data_freshness.py).

## Приоритезация проблем
- 🔴 Критично: данные не собираются, вердикты врут, сборщики упали.
- 🟡 Важно: расхождения, неполные данные, устаревшие описания.
- 🟢 Косметика: текст, цвета, форматирование.
- Явно указывать приоритет при информировании.

## Саймонсовский подход к проблемам
- Искать корень, а не симптомы.
- Пример: свечи перестали обновляться → коды истекли → нет автоопределения → добавили автоопределение.
- Не латать, а исправлять системно.

## Документирование
- Каждая найденная проблема → запись в WORK_LOG.
- Сохранять историю багов для анализа.

## Самостоятельное исправление
- Простые вещи (текст, опечатки, мелкие баги) — правлю сам, сообщаю.
- Сложные (архитектурные изменения) — обсуждаем сначала.

## Примеры проблем для выявления
- Расхождения между сводкой и сканером
- Тикеры с устаревшими данными (>3 дней)
- Противоречивые сигналы (LONG при CRISIS, бот vs сводка)
- Неполные данные (HI2, TradeStats отсутствуют)
- Ошибки в логах сборщиков
- Дубликаты файлов (старые и новые коды)
- Изменения API MOEX, влияющие на сборщики
